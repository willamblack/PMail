## Spec

独立 SMTP/配置审查原始 11 组发现，最严重等级 P1；不与 Standards 数量相加排名。

- “50 根域、任意层级子域、任意 local-part、统一 admin”：根域边界/IDNA 匹配和管理员 Catch-All 保持，未引入逐地址创建要求。
- “不能 Open Relay / 发件身份绕过”：修复 587 明文 AUTH、生产 `test.domain` DKIM 绕过、SPF 错用 Sender 头、SMTP 投递错误追加头部收件人。匿名外域 RCPT 拒绝仍保留。
- “保留完整原始 To 地址”：修复带逗号显示名/合法邮箱的解析、CID 丢失和重复附件；完整地址仍通过 To/Cc/Bcc 保留，**没有新增独立持久化信封来源字段**。
- “先保证功能、不大改后端”：修复畸形邮件崩溃、无效收件人假成功、MX 回退、发送超时及隐式 TLS 不校验证书；维持 API 和 SQLite 模型。
- “单一服务主机与 TLS”：修复 ACME map 并发、续期错误退出、证书写入路径、账号私钥权限和无效 PEM；没有进行公网证书签发验收。
- “旧配置兼容”：非法 JSON fail-closed，不会部分覆盖配置后错误进入初始化；相对 DKIM 路径修正；读取旧配置不会静默启用子域。

11 组详分为：明文 AUTH、DKIM 绕过、SPF 错误、信封收件人、MIME 解析、收件人/MX、出站 TLS/超时、ACME 并发/续期、配置加载、账号 PEM、CID/related。已局部修复。交叉复核还移除了生产发件路径里的 `test.domain → 127.0.0.1` 测试路由及敏感调试输出。

## 明确保留、没有隐瞒的问题

1. 旧密码存储仍为固定盐双 MD5，Token 协议与之绑定。安全迁移应设计 Argon2id/bcrypt、旧密码升级和应用令牌，不在本轮静默改变账号协议。请用长随机密码、限制管理入口、备份权限；这仍是安全债务。
2. 没有补齐完善的暴力登录/SMTP 滥用限制和每域配额。公网 Catch-All 可能受到垃圾邮件/磁盘耗尽攻击；需监控磁盘、连接和错误率，入口限制和备份不能省。
3. 出站仍是同步投递，没有成熟持久队列；多域部分成功后重试可能重复投递。TLS 仍有机会加密明文回退，不是强制 MTA-STS/DANE。SPF/DKIM 标志也不等于 DMARC 对齐。
4. IMAP 并非完整标准实现：Deleted 临时状态、SEARCH Deleted 的旧语义、跨会话序号/Poll/UIDNEXT、MIME partial FETCH、APPEND、分组重命名等仍需专项改造。已修误删不代表所有邮件客户端兼容。
5. POP3 旧 gopop STLS/编号/退出响应有协议问题；使用 995，建议纯 Web 用户不开放 110/995。没有 fork/vendor 改写整个依赖。
6. 原始信封地址没有独立持久化来源字段，To/Cc/Bcc 保留地址但不能完全区分头部与信封来源；搜索仍是 LIKE 扫描，未验证百万封邮件性能。
7. 邮件外部图片仍可加载，因此有发送者追踪风险；iframe 隔离解决执行/样式边界，不是隐私代理。
8. 未配置的首次安装向导本来就允许设置管理员：初始化阶段应限制入口；反代模式须由外层强制 HTTPS 并为会话 Cookie 设置 Secure，不能公网裸露容器 Web HTTP。
9. 前端开发依赖 8 项公告、离线训练工具边界问题和第三方压缩 jQuery 未全部处理，不声称全仓“零风险”。

对于当前“个人 admin + Web 通配收件”用途，本轮保留现有架构、优先修复安全和数据正确性；不建议为美观同时重写邮件内核。若以后要求完整 IMAP/POP3/持久发件队列，应单独评估成熟 MTA/IMAP 组合，不能继续用局部补丁承诺全面兼容。
